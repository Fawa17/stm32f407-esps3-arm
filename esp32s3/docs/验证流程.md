# 功能验证流程（从零到整机）

> 对象：STM32F407（`C:\STM32\smart hand`）+ ESP32-S3（`C:\STM32\hand_s3`）
> 原则：**分层验证**，每一层单独确认，出问题能立刻定位到"网络 / 协议 / 执行器"哪一段。

---

## 先解决最常见的两件事

### 1) 网页打不开

99% 是"电脑/手机没和 S3 在同一个网段"。按顺序查：

```powershell
netsh wlan show interfaces          # 看 SSID 是不是 ESP
```

- 如果 SSID 是别的（比如校园网 `Hohai University`、家里的 WiFi），**网页当然打不开** ——
  先连 `ESP` 热点：

```powershell
netsh wlan connect name="ESP" ssid="ESP" interface="WLAN"
```

- 连上后仍然打不开，说明 **IP 变了**（手机热点换网段，或者 DHCP 给了别的地址），
  直接跑：

```bat
C:\STM32\hand_s3\tools\find_s3.bat
```

S3 每 3 秒广播一次自己的地址，这个脚本一秒钟就能告诉你是 `http://172.19.62.xxx/`。

- 也可以从**手机**看：设置 → 个人热点 → 已连接的设备，里面直接显示 IP。

### 2) 上电默认是哪种模式

固件里 `DEFAULT_MODE 1` ⇒ **一连上网络就是"网络控制（远程）"**，
网页/接口说多少度就走多少度。

想切回体感：页面按「体感模式」，或

```bash
curl "http://172.19.62.150/api/mode?remote=0"
```

切换结果会被记住（`s_desired_mode`），STM32 单独重启后 S3 会自动补发
`M,0`/`M,1` 把它恢复成你选的那种。不再有"刚切完又被拉回体感"的情况。

## 第 0 层：不接任何硬件，先验证"算得对不对"

坐标解算是纯数学，跟硬件无关，所以先单独跑通。

**做法 A：网页里的 IK 验算台（F103 工程里那个，纯离线）**

双击 `C:\STM32\hand\sim\ik_lab.html`，输入坐标看能否解算、失败时给什么原因。

> 注意：那里的几何参数是早期尺子量的（8/10.5/14.5/19.5），
> 而 S3 现在用的是 CAD/网页那套（d1=10.831, A1=10.491, A2=11.820, A3=17.902）。
> 只用于看"算法逻辑"，数值以 S3 为准。

**做法 B：直接问 S3（不接 STM32 也能用）**

烧好 S3、连上热点后：

```bash
curl "http://172.19.62.150/api/cart?x=35&y=0&z=20&pitch=0"
```

期望：`{"ok":1,"angles":[90,96,12,84,90,25],...,"dev":0.012,...}`

这一步成功 = **WiFi + HTTP + IK 全通**，跟 STM32 一根线都没关系。
如果这步就失败，问题一定在 S3 侧，不要怀疑 STM32。

## 第 1 层：只烧 S3，确认网页和接口

1. `C:\STM32\hand_s3\build.bat flash 3`（COM 号按实际）
2. 手机/电脑连热点 `ESP`
3. 浏览器打开 `http://172.19.62.150/`

| 检查点 | 期望 |
|---|---|
| 页面能打开 | 显示"6 轴机械臂控制台"、6 个滑块、坐标输入框 |
| 顶部状态 | 「链路：离线」（此时 STM32 没接，**这是正常的**） |
| 滑块拖动 | 有日志输出，但机械臂不动（没接 STM32） |
| 坐标控制 | 能返回角度（纯 S3 计算） |

跑自动检查（只读模式，不会发动作命令）：

```bash
python C:\STM32\hand_s3\tools\verify_s3.py --no-motion
```

此时预期：网页、state、固件指纹 4 项 PASS；**链路 link=1 会 FAIL**，因为 STM32 还没接。

## 第 2 层：只烧 STM32，确认执行器

1. Keil 打开 `C:\STM32\smart hand\MDK-ARM\smart hand.uvprojx`，F8 烧录（SWD）
2. **先不要接 S3**，只接 MPU6050 + OLED + **1 个舵机**（PA0 底座，外部 5V）
3. 上电观察：

| 时间点 | 现象 |
|---|---|
| 0~1.2s | 六个通道依次启动（每 200ms 一路，避免冲击电流） |
| 1.2~2.7s | 从当前姿态**线性**走到 90° 中位（1.5s） |
| 常亮 | OLED 第一行 `ARM  LINK:---`（没有 S3 时为 ---/0） |
| 常亮 | OLED 有 `MODE:GESTURE`、`B090 S090 E090`… |
| 持续 | 手持 MPU6050 倾斜 → 底座舵机跟着左右转 |

如果 OLED 不亮：查 PB6/PB7 与 3.3V；如果某个舵机不动：查该轴引脚（PA0/PA1/PA2/PA3/PA6/PA7）。

## 第 3 层：全链路自动自检（推荐）

接好三根线（S3 GPIO17→PA10、GPIO18←PA9、GND），上电，然后：

```bat
C:\STM32\hand_s3\tools\verify_s3.bat
```

它会依次验证 **19 项**（约 15 秒）：

| 组 | 内容 |
|---|---|
| 网页 | 可访问、是控制台 |
| 状态 | JSON 合法、6 个角度、固件指纹 `s3-*`、**链路在线** |
| 模式 | 切远程生效 |
| 姿态 | 发 `P,90,90,90,90,90,25` → 机械臂真的走到（±3°） |
| 夹爪 | 闭合 135° / 张开 25° |
| 杂项 | query、stop |
| 坐标 | 可达点 `dev<0.5cm`；不可达点返回中文原因 |
| 计数 | `cmd` 递增（证明命令确实进了 STM32） |

全绿表示：**WiFi → HTTP → 串口协议 → 插值 → PWM** 整条链路通。

失败时的定位口诀：

| 失败项 | 说明问题在哪 |
|---|---|
| 网页打不开 | S3 没起来 / IP 不对 / 不在同一热点 |
| `fw` 不是 `s3-*` | 烧的是旧固件 |
| `link=0` | 串口三根线（TX/RX 是否交叉、GND）或 STM32 没跑起来 |
| `link=1` 但舵机不动 | STM32 侧 PWM/舵机供电问题（看 OLED 的 `B/S/E` 数字有没有变） |
| 姿态停在半路 | 电源带不动 6 个舵机（量 5V 是否跌到 4.6V 以下） |
| 坐标 `ok=0` | 正常（点不可达），看 `err` 文案即可 |

## 第 4 层：手感与性能验收

| 项 | 期望 | 怎么试 |
|---|---|---|
| 关节速度 | 180°/s | 拖滑块从 30 到 150，计时应 ≈0.67s |
| 夹爪速度 | 600°/s | 夹爪 25↔135，计时应 ≈0.18s |
| 跟随延迟 | <100ms | 手机拖滑块，肉眼应几乎同步 |
| 平滑度 | 无台阶、无猛停 | 大幅连续拖动，观察是否梯形加减速 |
| 体感模式 | 倾斜 → 机械臂跟 | 页面点「体感模式」后晃动手持传感器 |
| 急停 | 立即停住并保持 | 点「急停」，之后不再被新目标覆盖 |

---

## 第 5 层：异常与恢复

| 场景 | 期望 |
|---|---|
| 拔掉 S3 的 TX（PA10 那根） | 网页 3~6 秒内变「链路离线」，机械臂保持最后姿态不动 |
| 插回 | 自动恢复，无需重启 |
| 关掉网页 | 机械臂继续执行最后目标（STM32 自己插值） |
| 按住 STM32 复位 | 重新软启动 → 回中位；S3 侧自动补发 `H,1`/`Q` 恢复链路 |
| S3 断电重启 | 重新连 WiFi，拿回状态 |

## 手工核对（不用脚本时）

```bash
# 状态
curl "http://172.19.62.150/api/state"

# 切成远程（发动作前必须先做这步）
curl "http://172.19.62.150/api/mode?remote=1"

# 六个角度直接给
curl "http://172.19.62.150/api/pose?angles=90,120,60,90,90,25&ms=0"

# 单轴点动（标定用）：axis 0~5，deg 正负表示方向
curl "http://172.19.62.150/api/jog?axis=1&deg=+10"

# 夹爪 0=闭合 1=张开
curl "http://172.19.62.150/api/gripper?open=1"

# 急停 / 查询
curl "http://172.19.62.150/api/stop"
curl "http://172.19.62.150/api/query"
```

**没有 S3 时如何单独测 STM32？**
用 USB-TTL 接 PA9(TX)/PA10(RX)/GND，波特率 115200，用串口助手发文本行（结尾 `\n`）：

```
Q                      → 回 ST,0,90,90,90,90,90,25,1
M,1                    → 回 OK，进入远程
P,90,120,60,90,90,25   → 回 OK，机械臂平滑走过去
G,1                    → 回 OK，夹爪张开
S                      → 回 OK，停住
```
